Docker Deployment

The recommended way to deploy the MCP server is using Docker with multi-stage builds for optimized production images.

Prerequisites

  • Docker 20.10+
  • Docker Compose 2.0+ (optional, for orchestration)
  • Veradigm FHIR API credentials

Build Docker Image

# Build the Docker image docker build -t veradigm-fhir-mcp-server . # Tag for production registry (optional) docker tag veradigm-fhir-mcp-server registry.example.com/veradigm-fhir-mcp-server:1.0.0

Docker Multi-Stage Build

The Dockerfile uses a multi-stage build process:

Run Container

# Run with environment variables docker run -d \ --name veradigm-fhir-mcp-server \ -e NODE_ENV=sandbox \ -e CLIENT_ID=your-client-id \ -e CLIENT_SECRET=your-client-secret \ -e FHIR_BASE_URL_SANDBOX=https://fhir.fhirpoint.open.allscripts.com/fhirroute/fhir/CP00101 \ -e TOKEN_URL_SANDBOX=https://fhir.fhirpoint.open.allscripts.com/fhirroute/authorizationV2/CP00101/connect/token \ -e AUTH_URL_SANDBOX=https://fhir.fhirpoint.open.allscripts.com/fhirroute/authorizationV2/CP00101/connect/authorize \ -e TOKEN_CACHE_TTL=3600 \ -e CACHE_ENABLED=true \ -e LOG_LEVEL=info \ veradigm-fhir-mcp-server

Docker Compose Deployment

Use Docker Compose for easier orchestration and management:

docker-compose.yml

version: '3.8' services: veradigm-fhir-mcp-server: build: context: . dockerfile: Dockerfile target: production container_name: veradigm-fhir-mcp-server environment: - NODE_ENV=${NODE_ENV:-sandbox} - CLIENT_ID=${CLIENT_ID} - CLIENT_SECRET=${CLIENT_SECRET} - FHIR_BASE_URL_SANDBOX=${FHIR_BASE_URL_SANDBOX} - TOKEN_URL_SANDBOX=${TOKEN_URL_SANDBOX} - AUTH_URL_SANDBOX=${AUTH_URL_SANDBOX} # ... other environment variables restart: unless-stopped healthcheck: test: ["CMD", "node", "-e", "console.log('Health check passed')"] interval: 30s timeout: 10s retries: 3

Deploy with Compose

# Create .env file with your credentials cat > .env << EOF NODE_ENV=sandbox CLIENT_ID=your-client-id CLIENT_SECRET=your-client-secret FHIR_BASE_URL_SANDBOX=https://fhir.fhirpoint.open.allscripts.com/fhirroute/fhir/CP00101 TOKEN_URL_SANDBOX=https://fhir.fhirpoint.open.allscripts.com/fhirroute/authorizationV2/CP00101/connect/token AUTH_URL_SANDBOX=https://fhir.fhirpoint.open.allscripts.com/fhirroute/authorizationV2/CP00101/connect/authorize EOF # Build and start docker-compose up --build -d # View logs docker-compose logs -f # Stop docker-compose down

Environment Variables

All configuration is done via environment variables:

Variable Required Default Description
NODE_ENV No sandbox Environment: 'sandbox' or 'production'
CLIENT_ID Yes - OAuth 2.0 client ID
CLIENT_SECRET Yes - OAuth 2.0 client secret
FHIR_BASE_URL_SANDBOX Yes (sandbox) - FHIR API base URL for sandbox
FHIR_BASE_URL_PRODUCTION Yes (production) - FHIR API base URL for production
TOKEN_URL_SANDBOX Yes (sandbox) - OAuth token endpoint for sandbox
TOKEN_URL_PRODUCTION Yes (production) - OAuth token endpoint for production
AUTH_URL_SANDBOX Yes (sandbox) - OAuth authorization endpoint for sandbox
AUTH_URL_PRODUCTION Yes (production) - OAuth authorization endpoint for production
TOKEN_CACHE_TTL No 3600 Token cache TTL in seconds
CACHE_ENABLED No true Enable token caching
LOG_LEVEL No info Logging level: debug, info, warn, error

Local Development

Prerequisites

  • Node.js 18+
  • npm or yarn
  • TypeScript 5.0+

Setup

# Install dependencies npm install # Create .env file cp .env.example .env # Edit .env with your credentials # Build TypeScript npm run build # Run in development mode npm run dev # Run production build npm start

Development with Hot Reload

# Install nodemon globally npm install -g nodemon # Run with auto-reload nodemon --exec ts-node src/index.ts

Cloud Deployment

AWS ECS / Fargate

Note: MCP servers use stdio transport, so they're typically deployed as sidecar containers or run directly on the host.

Kubernetes

Deploy as a Kubernetes Deployment:

apiVersion: apps/v1 kind: Deployment metadata: name: veradigm-fhir-mcp-server spec: replicas: 1 selector: matchLabels: app: veradigm-fhir-mcp-server template: metadata: labels: app: veradigm-fhir-mcp-server spec: containers: - name: mcp-server image: veradigm-fhir-mcp-server:1.0.0 env: - name: CLIENT_ID valueFrom: secretKeyRef: name: veradigm-secrets key: client-id # ... other environment variables

Azure Container Instances

# Deploy to Azure Container Instances az container create \ --resource-group myResourceGroup \ --name veradigm-fhir-mcp-server \ --image veradigm-fhir-mcp-server:1.0.0 \ --environment-variables \ NODE_ENV=sandbox \ CLIENT_ID=your-client-id \ --secure-environment-variables \ CLIENT_SECRET=your-client-secret

Google Cloud Run

# Build and push to GCR gcloud builds submit --tag gcr.io/PROJECT_ID/veradigm-fhir-mcp-server # Deploy to Cloud Run gcloud run deploy veradigm-fhir-mcp-server \ --image gcr.io/PROJECT_ID/veradigm-fhir-mcp-server \ --set-env-vars NODE_ENV=sandbox,CLIENT_ID=your-client-id \ --set-secrets CLIENT_SECRET=client-secret:latest

Health Checks

The Docker container includes health checks:

HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \ CMD node -e "console.log('Health check passed')" || exit 1

Monitoring

  • Check container health: docker ps
  • View health check logs: docker inspect --format='{{json .State.Health}}' container-name
  • Monitor logs: docker logs -f veradigm-fhir-mcp-server

Security Best Practices

⚠️ Security Considerations:
  • Never commit secrets: Use environment variables or secrets management
  • Use non-root user: Dockerfile runs as non-root user 'mcp'
  • Minimal base image: Uses Alpine Linux for smaller attack surface
  • Token caching: Tokens are cached in memory only, never persisted
  • Network security: Ensure container network is properly secured
  • Secrets management: Use Docker secrets, Kubernetes secrets, or cloud secret managers

Secrets Management

# Use Docker secrets echo "your-client-secret" | docker secret create client_secret - # Use in docker-compose.yml secrets: - client_secret environment: - CLIENT_SECRET_FILE=/run/secrets/client_secret

Troubleshooting

Common Issues

Container won't start

  • Check environment variables are set correctly
  • Verify CLIENT_ID and CLIENT_SECRET are valid
  • Check logs: docker logs veradigm-fhir-mcp-server

Authentication errors

  • Verify OAuth endpoints are correct
  • Check client credentials are registered for the endpoint
  • Verify network connectivity to OAuth server
  • Check token cache TTL matches token expiration

FHIR API errors

  • Verify FHIR base URL is correct
  • Check token has required scopes (system/*.read)
  • Verify client has permissions for requested resources
  • Check network connectivity to FHIR server

Debug Mode

# Run with debug logging docker run -e LOG_LEVEL=debug veradigm-fhir-mcp-server
