Integration with RetellAI

The Veradigm FHIR MCP Server is designed to integrate seamlessly with RetellAI voice agents for healthcare call handling.

Integration Architecture

RetellAI Configuration

1 Configure MCP Server Connection

In RetellAI, configure the MCP server connection:

# RetellAI MCP Configuration { "mcpServers": { "veradigm-fhir": { "command": "docker", "args": [ "run", "--rm", "-i", "-e", "CLIENT_ID=your-client-id", "-e", "CLIENT_SECRET=your-client-secret", "veradigm-fhir-mcp-server:latest" ] } } }
2 Configure Voice Agent Prompts

Create prompts that instruct the AI to use MCP tools:

# Example RetellAI Prompt You are a healthcare assistant for Idaho Kidney Institute. When a patient calls: 1. First, verify their identity using the search_patient tool with: - Name (first and last) - Date of birth 2. Once verified, you can: - Check upcoming appointments using get_upcoming_appointments - Confirm appointment attendance - Check medication refills using get_patient_medications - Transfer to appropriate provider using search_providers Always be professional, empathetic, and HIPAA-compliant.
3 Test Integration

Test the integration with sample calls:

  • Patient verification call
  • Appointment confirmation call
  • Medication refill request
  • Call transfer scenario

Example Integration Scenarios

Scenario 1: Patient Verification

# Call Flow 1. Patient calls: "Hi, this is John Doe, I need to confirm my appointment" 2. AI uses search_patient tool: { "name": "John Doe" } 3. If multiple matches, ask for DOB: "I found a few John Does. Can you please provide your date of birth?" 4. Verify with DOB: { "name": "John Doe", "birthDate": "1990-01-01" } 5. Once verified, proceed with appointment check

Scenario 2: Appointment Confirmation

# After patient verification 1. AI uses get_upcoming_appointments: { "patientId": "patient-123", "limit": 5 } 2. AI responds with appointment details: "You have an appointment on January 15th at 2:00 PM with Dr. Smith" 3. Patient confirms: "Yes, I'll be there" (Note: Confirmation requires write operations - Phase 2)

Scenario 3: Medication Refill Request

# Patient requests refill 1. AI uses get_patient_medications: { "patientId": "patient-123", "status": "active" } 2. AI lists medications: "You have the following active medications: - Lisinopril 10mg, daily - Metformin 500mg, twice daily" 3. Patient: "I need a refill for Lisinopril" 4. AI uses check_refill_status to check eligibility 5. AI confirms and creates refill request (Note: Creating requests requires write operations - Phase 2)

Scenario 4: Call Transfer

# Patient needs to speak with provider 1. Patient: "I need to speak with Dr. Smith" 2. AI uses search_providers: { "name": "Smith" } 3. AI finds provider and gets details: { "providerId": "provider-456" } 4. AI: "I'll transfer you to Dr. Smith now. Please hold." 5. Transfer call to provider's extension

MCP Protocol Integration

The MCP server uses stdio transport and JSON-RPC 2.0 protocol.

Tool Discovery

# Request: List available tools { "jsonrpc": "2.0", "method": "tools/list", "id": 1 } # Response: List of all 20+ tools { "jsonrpc": "2.0", "id": 1, "result": { "tools": [ { "name": "search_patient", "description": "Search for patients...", "inputSchema": { ... } }, ... ] } }

Tool Execution

# Request: Call a tool { "jsonrpc": "2.0", "method": "tools/call", "params": { "name": "search_patient", "arguments": { "name": "John Doe", "birthDate": "1990-01-01" } }, "id": 2 } # Response: Tool result { "jsonrpc": "2.0", "id": 2, "result": { "content": [ { "type": "text", "text": "{\"patients\": [...], \"total\": 1}" } ] } }

Best Practices

Error Handling

  • Always handle errors gracefully in voice responses
  • Provide fallback options when tools fail
  • Log errors for debugging and monitoring

Patient Privacy (HIPAA)

  • Always verify patient identity before accessing data
  • Use minimum necessary data access
  • Log all data access for audit trails
  • Never store patient data in logs or cache

Performance

  • Cache tokens to reduce authentication overhead
  • Use pagination for large result sets
  • Limit search results to reasonable sizes
  • Implement timeout handling for long-running operations

Voice Agent Design

  • Use natural language in prompts
  • Guide users through verification step-by-step
  • Provide clear confirmation messages
  • Offer to transfer to human when needed
