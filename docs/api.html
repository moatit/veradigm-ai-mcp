MCP Protocol

The Veradigm FHIR MCP Server implements the Model Context Protocol 2.0 specification. All tools are accessed via MCP protocol messages.

Protocol Transport

The server uses stdio transport for MCP communication. Tool calls are made via JSON-RPC 2.0 messages.

Request Format

{ "jsonrpc": "2.0", "method": "tools/call", "params": { "name": "search_patient", "arguments": { "name": "John Doe", "birthDate": "1990-01-01" } }, "id": 1 }

Response Format

{ "jsonrpc": "2.0", "id": 1, "result": { "content": [ { "type": "text", "text": "{\"patients\": [...], \"total\": 1}" } ] } }

Patient Tools

search_patient
Search for patients by various criteria including name, birth date, gender, phone, email, or MRN.

Parameters

Parameter Type Required Description
name string Optional Full name to search for
firstName string Optional First name (if not using 'name')
lastName string Optional Last name (if not using 'name')
birthDate string Optional Birth date in YYYY-MM-DD format
gender string Optional Gender: male, female, other, unknown
phone string Optional Phone number
email string Optional Email address
mrn string Optional Medical Record Number
limit number Optional Maximum results (default: 20)

Response

{ "patients": [ { "id": "patient-123", "name": "John Doe", "firstName": "John", "lastName": "Doe", "birthDate": "1990-01-01", "gender": "male", "phone": "555-123-4567", "email": "john.doe@email.com", "mrn": "MRN123456", "active": true } ], "total": 1, "hasMore": false }
get_patient_details
Get detailed information for a specific patient by ID.

Parameters

Parameter Type Required Description
patientId string Required FHIR Patient resource ID

Response

{ "id": "patient-123", "name": "John Doe", "firstName": "John", "lastName": "Doe", "birthDate": "1990-01-01", "gender": "male", "phone": "555-123-4567", "email": "john.doe@email.com", "address": "123 Main St, City, ST 12345", "mrn": "MRN123456", "active": true }
verify_patient_identity
Verify patient identity by matching provided information against patient records.

Parameters

Parameter Type Required Description
firstName string Optional First name
lastName string Optional Last name
birthDate string Optional Birth date in YYYY-MM-DD format
phone string Optional Phone number
email string Optional Email address
mrn string Optional Medical Record Number

Note: At least one parameter is required.

Response

{ "verified": true, "patient": { "id": "patient-123", "name": "John Doe" // ... full patient object }, "matchScore": 1.0, "suggestions": [] }

Error Responses

All tools return structured error responses when errors occur:

{ "error": "VALIDATION_ERROR", "message": "Patient ID is required", "details": "Additional error details", "timestamp": "2024-01-01T12:00:00Z" }

Error Types

  • VALIDATION_ERROR: Invalid input parameters
  • AUTHENTICATION_ERROR: OAuth token issues
  • NOT_FOUND_ERROR: Resource not found
  • PERMISSION_ERROR: Insufficient permissions (403)
  • FHIR_API_ERROR: FHIR API errors
  • NETWORK_ERROR: Network connectivity issues
  • UNKNOWN_ERROR: Unexpected errors
